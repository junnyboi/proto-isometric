## 1. Visual contract

The concept package translates the approved Living Settlement design into a coherent interface language: **near-black translucent glass, oxidized-teal structure, cyan operational information, amber consequential actions, muted red danger, slate disabled states, compact technical typography, and persistent live-world context**. The two user-supplied references establish composition, density, material, color, and hierarchy. They are visual references only and are not copied into the repository.

All interactive screens must be implemented with native Godot Controls, localized text, authoritative projections, and semantic input. These images are not legal gameplay state, hit geometry, exact copy, or reusable flattened panels. Generated facts, counts, labels, and layouts must be replaced by data sourced from validated runtime contracts.

## 3. Runtime asset production rule

Runtime raster assets are generated **per work package** with GPT Image 2 rather than cropped blindly from these text-bearing boards. Each item or tightly related family receives a dedicated master with locked perspective, palette, lighting, silhouette scale, and transparent-background instructions. Deterministic tools may crop, resize, chroma-remove, pack, and compress generated pixels; they may not invent or redraw semantic content.

Every shipped raster asset requires:

1. a stable runtime ID and catalog owner;
2. the GPT Image 2 prompt and generation date;
3. source and optimized dimensions;
4. deterministic processing commands or script;
5. source and runtime SHA-256 values;
6. decoded-memory and download budgets;
7. alpha-edge and small-scale legibility checks;
8. explicit Web export inclusion and integrity tests;
9. landscape and portrait visual evidence;
10. a source manifest next to its runtime family.

Icons must be generated as **standalone isolated files or small semantically coherent families**. One-shot dense atlases are not accepted as runtime masters because background cleanup, cell alignment, and silhouette consistency become needlessly fragile. Atlas packing happens only after individual assets pass review. A tiny procedural fallback icon remains available for missing or unknown IDs.

## 5. Acceptance boundary

A work package has not matched the concept merely because its screenshot is dark and cyan. It must reproduce the **hierarchy, live-world preservation, causal information, restrained semantic color, consistent spacing, responsive posture, and immediate distinction between information, warning, consequence, and danger**. Conversely, exact concept copy, counts, percentages, or button labels are rejected when no authoritative gameplay contract supplies them.
