# Walker's Wake Implementation Plan

**Plan status:** Approved; packages `WW-01` through `WW-23` are implemented.

**Pinned baseline:** `a30db57ca5d8b43771b9bc1363368e4d397057f6` (`a30db57`)

**Engine and target:** Godot 4.7.1, desktop and Web, with desktop keyboard/pointer and mobile coarse-pointer/touch parity.

## 1. Purpose and decision summary

This plan turns the approved Walker's Wake gameplay proposal into a dependency-aware implementation sequence grounded in the repository at commit `a30db57`. It schedules no immediate implementation. Its purpose is to define contracts, sequencing, acceptance criteria, likely files, focused research questions, and rollback points before runtime work starts.

The core product decision is an 8–12 minute expedition built around direct control of Cardinal: drive, build Impact Charge, Smash, activate three relays, survive Alert escalation, use harvested outposts as sanctuaries and Refit stations, then extract to bank the run or fail with a fair loss. The implementation must make existing systems collide more deliberately rather than add a large ability bar or unrelated enemy catalogue.

The proposal and the shipped runtime disagree about Aftershock. The repository already ships the 80–100% three-cell fan, extra debris, and a brief surviving-worm stagger. That accepted behavior is Cardinal's baseline and must remain available on fresh and migrated saves. The Refit module named **Aftershock** therefore improves the existing high-charge fan instead of unlocking, removing, or re-gating it. Its first-tier effect is a data-driven, capped extension to stagger and Expose vulnerability on a valid high-charge hit, with stronger but bounded feedback; it does not add damage, a new input, a second fan implementation, or a larger footprint.

The proposal's “Launch with one starter module” wording is normalized as a **starter module slot and three-path build opportunity**, not a free tier-one effect. The first effective one-run module is purchased at a harvested outpost during the active expedition. This preserves the proposed Worm Core economy and avoids granting a supposedly Core-gated effect before a Core can be earned. Refit remains available during an active run before extraction. After relay three, exact-cell outpost arrival extracts automatically; the terminal sequence is summary and modifier choice, not a purchase of a run-only module that would immediately expire.

## 3. Design invariants

These invariants are acceptance constraints, not tuning suggestions. A package that violates one remains incomplete even if its new feature works in isolation.

| Invariant | Required interpretation |
|---|---|
| Cardinal control | Desktop retains direct eight-direction WASD/arrows, Shift run, acceleration, coasting, and one contact-frame Smash. Mobile retains one floating joystick and one Smash button. No interaction, relay, ability, Ram, Core, extraction, or modifier button is added to the field. |
| Impact baseline | Contact, two-cell line, and the shipped 80–100% three-cell fan remain available. One attack consumes charge once at the existing contact frame. Aftershock improves valid high-band worm stagger/vulnerability and presentation; it never removes or re-gates the fan. |
| Automatic interactions | Scrap and Core collection, relay linking, sanctuary detection, and extraction remain automatic by position. Menu cards use standard pointer, keyboard, and touch activation only while field input is suspended. |
| Cardinal identity | Cardinal remains a 6–8 meter, compact, broad, hunchbacked, gorilla-like industrial colossus with a rounded headless torso, enormous near-ground forearms, blocky fists, short sturdy legs, bone-tan/faded-peach armor, charcoal mechanisms, dark seams, worn edges, and no dominant guns. Tall humanoid proportions, sleek armor, long legs, small arms, a mounted city, or weapon-rack drift are rejected. |
| Projection and readability | World art uses the exact 2:1 isometric perspective. Terrain and gameplay geometry remain readable before decoration. Teal means route/link/sanctuary, amber means danger and charged impact, and red means lethal shutdown; labels, silhouettes, patterns, or motion duplicate color meaning. |
| Infinite streaming | The runtime remains deterministic and practically unbounded while retaining exactly the bounded 5×5 chunk ring, no more than 1,600 active streamed cells, and no more than 841 visible render cells under normal configuration. Objectives, drops, VFX, and cosmetic variants cannot pin distant chunks. |
| State ownership | `isometric_map.gd` is the composition adapter. `RunCoordinator` owns lifecycle and economy, `RunState` owns resumable expedition data, `ProfileState` owns banked progression and pending offers, `InfiniteWorld` owns deterministic world mutations, and presentation reads immutable view models. No UI, enemy, or renderer mutates currency or settlement. |
| Alert truth | Alert equals `clamp(credited relay completions, 0, 3)`. It is derived, not independently mutable. Relay one completion activates Alert I toward relay two; relay two activates Alert II toward relay three; relay three activates Alert III for extraction. |
| Encounter direction | Alert changes combinations, routes, and timing instead of inflating worm health. Alert I is one hunter, Alert II is a hunter plus bounded telegraphing dust devils, and Alert III is one hunter during one broad readable storm front. |
| Sanctuary and service | A sanctuary radius suppresses new director-owned pressure and disperses director-owned worms without lowering durable Alert. Exact-cell outpost presence retains repair/Refit service and is the only extraction trigger. |
| Run economy | Newly collected scrap and Worm Cores are unbanked active-run resources. World mutations always persist. One-run modules persist across ordinary reload of the same expedition and reset on committed success or failure. |
| Settlement | Success and failure are previewed and committed exactly once under a stable `settlement_id`. Save acknowledgement precedes presentation or irreversible cleanup. Success banks relay data and permitted resources. Failure banks no relay data, loses all unbanked Cores, and by default loses 50% of unbanked scrap using `lost = ceil(scrap × 0.5)` and `retained = scrap - lost`; the retained amount becomes rescued starting scrap for the next expedition, not profile bank. |
| Save compatibility | Valid schema-1 and schema-2 saves load without losing terrain mutations, scrap availability, chassis, robot cell, facing, starter relay state, or shutdown state. Future, malformed, oversized, and interrupted saves fail without partially mutating runtime state. |
| Deterministic resume | Transient enemies, hazard nodes, particles, timers, camera shake, audio, UI focus, and partial relay link progress are not serialized. Resume reconstructs a fair checkpoint from durable phase, objectives, applied-event sets, and player state without replaying rewards or unavoidable contact damage. |
| Reversible presentation | Icons, sprites, VFX atlases, card art, key art, shaders, particles, audio, copy, camera impulse, and timing polish remain replaceable. Hit tests, costs, arithmetic, telegraph boundaries, progress, focus, and collision never depend on raster art. |
| Lean execution | Each package states only its goal, affected area, and done condition. Implementation uses focused tests, one release verification flow, a Git checkpoint, and rollback through the previous commit or WebDev checkpoint; no duplicate process artifact is created. |

## 4. Target architecture and likely files

The target architecture is event-driven but deliberately local to the field scene. New services should be `RefCounted`, `Resource`, or child `Node` types constructed by `isometric_map.gd`, not global Autoloads, unless a later engine limitation is documented in this plan.

| Responsibility | Existing or likely file | Contract |
|---|---|---|
| Composition adapter | `scripts/isometric_map.gd` | Builds services after load, forwards semantic input/world events, applies coordinator outputs, and owns no lifecycle/economy truth. It remains the only hot integration seam for player movement and contact-frame attacks. |
| Run authority | New `scripts/run_coordinator.gd` | Validated lifecycle transitions, event idempotency, resource transactions, objective credit, derived Alert, service eligibility, settlement, and relaunch. Emits typed signals and immutable projections. |
| Resumable run model | New `scripts/run_state.gd` | Stable `run_id`, seed, phase, resume position/facing/chassis, objectives, unbanked wallets, module levels, active modifier, applied event IDs, transient run-pickup records, and pending settlement. Provides strict dictionary boundaries. |
| Persistent profile | New `scripts/profile_state.gd` | Banked relay data, banked resource counters if retained for future unlocks, success/failure counts, pending modifier offer, selected next modifier, and minimal last-run summary. No terrain mutations. |
| Settlement | New `scripts/run_settlement.gd` | Immutable preview/result records and policy-specific success/failure arithmetic. Uses stable settlement IDs and has no UI dependency. |
| Save repository | New `scripts/save_repository.gd` | Owns schema-3 envelope, detached validation, metadata inspection, repository transaction boundaries, backup selection, and commit acknowledgement. |
| Save migrations | New `scripts/save_migrator.gd` | Pure `1→2` and `2→3` transformations with fixture-backed canonicalization. Never mutates live world state. |
| Atomic transport | Existing `scripts/world_state_store.gd` | Same-directory temporary write, flush, backup, atomic replacement, primary/backup load candidates, diagnostic quarantine, and coarse transport errors. It does not know game schema. |
| World generation/mutations | Existing `scripts/infinite_world.gd` | Deterministic terrain and permanent rock/scrap mutation authority; pure terrain/outpost/relay-candidate queries; no active-run wallets or transient enemy state. |
| Run-only pickups | New `scripts/run_pickups.gd` | Chunk-indexed uncollected Core and bonus-scrap records stored inside `active_run`, automatic collection, deterministic fallback placement, culling, hard caps, and no permanent world-delta keys. |
| Expedition layout | New `scripts/expedition_layout.gd` and `scripts/relay_objective.gd` | Bounded deterministic relay candidate search using seed and `world_generation_version`; stores three stable objective IDs/cells. Relay one remains the starter cell for compatibility. |
| Relay runtime | New `scripts/relay_registry.gd`, existing `scripts/relay_contest.gd` | Registry materializes only nearby contests. `RelayContest` gains ID and active state but keeps automatic radius, 3.5-second link, exit reset, and one-shot signals. |

| Worm telegraphs/presentation | New `scripts/sandworm_telegraphs.gd`, optional `scripts/worm_visuals.gd` | Consumes read-only snapshots and renders bounded ridge history, intercept geometry, vulnerability cues, and optional authored assets without changing simulation. |
| Module catalogue/economy | New `scripts/module_definition.gd`, `scripts/refit_service.gd`, `scripts/module_effects.gd`, `data/modules/*.tres` | Stable IDs, costs, levels, capability tags, atomic purchase, and typed adapters for Ram Plating, Aftershock enhancement, and Storm Seal. |
| Modifier catalogue | New `scripts/run_modifier_definition.gd`, `scripts/modifier_service.gd`, `data/run_modifiers/*.tres` | Stable IDs, deterministic two-choice offers, compatibility tags, neutral defaults, and typed consumers for Hot Front, Brood Ground, and Dead Grid. |
| Field presentation model | New `scripts/field_ui_state.gd`, existing `scripts/field_hud.gd` | Chassis, Impact band, run scrap, Cores, relay count/progress, Alert, active modifier, objective guidance, contextual event, and debug-only telemetry. No dictionaries from gameplay systems. |
| Modal UI | Existing `scripts/outpost_interface.gd`; new `scripts/run_summary.gd`, `scripts/modifier_choice.gd`, `scripts/accessibility_menu.gd` | Native Godot Controls with immutable view models and emitted intents. Pointer, keyboard, and touch share the same command methods. |
| Mobile parity | Existing `scripts/mobile_controls.gd` | Safe-area layout, explicit touch ownership, outer-ring run intent with hysteresis, one Smash button, and input suspension/cancellation while modals are open. |
| Preferences/onboarding | New `scripts/player_preferences.gd`, `scripts/field_onboarding.gd` | Separate atomic ConfigFile at `user://walkers-wake-settings.cfg`; semantic fact-based tutorial, accessibility, handedness, and feedback preferences; no world-save schema coupling. |

## 5. Dependency-aware phase roadmap

The roadmap is sequenced around irreversible contracts. Foundation and schema recovery precede new persisted features. Worm rewards precede Refit economy. Stable relay records precede Alert and extraction. Settlement precedes modifiers and title replay. UX can research early but integrates against stable view models. Final balance begins only after the complete loop exists.

| Phase | Dependency and scope | Playable checkpoint | Exit dependency |
|---|---|---|---|
| A. Foundation | Freeze IDs, lifecycle, state categories, balance/telemetry vocabulary, field presentation model, release evidence, run authority, and recoverable schema 3. No visible gameplay change. | The current one-relay game plays identically through typed state and repository boundaries; schema-1/2 saves migrate and backup recovery works. | Required before any package writes Cores, module state, multiple relays, settlement, or modifiers. |
| B. Worm counterplay and Cores | Add deterministic worm states, readable telegraphs, Expose-only damage, baseline high-charge stagger extension, exactly-once defeat, run-only Core/scrap drops, collection, HUD, and persistence. | A player can read the ridge/amber intercept, dodge, turn, Smash during Expose, finish a skilled fight under 25 seconds, collect one Core plus scrap, reload, or retreat. | Reward and wallet contracts feed Refit and settlement. |
| C. Refit and one-run upgrades | Add module definitions, atomic purchase, responsive three-card Refit, Ram Plating, baseline-preserving Aftershock improvement, Storm Seal, and one purchase allowance per active run. | At a harvested outpost, a player understands and buys one effect in under 15 seconds, then observes the effect without gaining a new field verb. | Module reset and spend summaries feed success/failure settlement. |
| D. Three-relay Alert run | Create deterministic three-objective layout/registry, compact guidance, EncounterDirector, sanctuary radius, and Alert I–III in separate playable increments. | Relay one remains nearby; two later relays stream safely; Alert compositions escalate from worm to worm+dust to worm+broad storm; relay three marks extraction ready. | Stable objective and encounter state enables production extraction. |
| E. Extraction, failure, and banking | Add exact-cell automatic success settlement, fair failure settlement, world-mutation preservation, summary, title Continue metadata, and recoverable pending presentation. | Three relays plus any outpost banks once; field shutdown loses all Cores and configured scrap portion once, then offers an immediate mobile-safe retry. | Terminal state and profile bank enable modifier offers and next-run reset. |
| F. Modifiers and replayability | Add deterministic two-of-three offers, next-run promotion, Hot Front, Brood Ground, Dead Grid, and one atomic relaunch transaction. | Success produces two persisted choices; one applies to exactly the next run; failure produces no offer; a second expedition starts cleanly with world/profile retained. | Complete gameplay loop is ready for onboarding, full accessibility hardening, and balance. |
| G. UX, onboarding, and accessibility | Finalize decision HUD, mobile run parity, semantic onboarding, settings/preferences, captions/audio/haptics, responsive title/summary, and non-color cues. Research begins in Phase A; integration follows stable models. | A new player answers where to go, why to keep moving, and when to Smash; default, large-text, reduced-motion, muted, left-handed, and narrow layouts remain playable. | Required before final public certification. |
| H. Balance, visuals, performance, and release | Run telemetry-guided tuning, complete coherent GPT Image 2 asset integration, ten-run soak, save fuzz, browser performance, exact bundle deployment, accessibility audit, and launch presentation. | Representative successful runs take 8–12 minutes, all thresholds pass, no monotonic growth appears, and the exact public build matches the pushed checkpoint. | Final definition of done. |

## 7. Save schema 3 and migration strategy

Schema 3 is an envelope, not an extension of the flat world dictionary. World-generation compatibility and save-envelope compatibility are versioned separately. JSON keys use stable strings, stable IDs are stored rather than resource paths or array indices, and enum values are serialized as strings rather than ordinals.

```json
{
  "save_format_version": 3,
  "metadata": {
    "build_id": "<commit-or-release-id>",
    "world_generation_version": 1,
    "write_sequence": 17,
    "saved_at_unix": 0,
    "migration_source": 2
  },
  "world": {
    "destroyed_rocks": [],
    "placed_rocks": [],
    "dropped_scrap": [],
    "collected_scrap": []
  },
  "active_run": {
    "run_id": "run-...",
    "run_seed": 0,
    "phase": "HUNT",
    "player": {"cell": [8, 10], "facing": "SE", "chassis": 100},
    "objectives": [],
    "unbanked_scrap": 0,
    "worm_cores": 0,
    "modules": [],
    "active_modifier_id": "neutral",
    "run_pickups": [],
    "applied_event_ids": [],
    "pending_settlement": null
  },
  "profile": {
    "banked_relay_data": 0,
    "banked_scrap": 0,
    "banked_cores": 0,
    "successful_runs": 0,
    "failed_runs": 0,
    "pending_modifier_offer": null,
    "next_modifier_id": "neutral",
    "last_run_summary": null
  }
}
```

The illustrative structure does not freeze exact JSON spelling until `WW-01` and `WW-03` close, but it freezes section ownership. `world` contains only deterministic permanent deltas. `active_run` contains the resumable expedition and run-only pickups. `profile` contains banked facts and pending replay choices. Metadata timestamps are presentation-only and never affect deterministic generation or offer outcomes.

| Migration or recovery case | Canonical behavior |
|---|---|
| Schema 1 | Validate the finite 18×18 fields with current semantics, transform surviving/removed rocks and scrap into canonical world deltas, preserve robot cell/facing/chassis/scrap where present, then transform through schema 2 to schema 3 in memory. The original file remains untouched until full schema-3 validation and a later normal save. |
| Schema 2, relay false | Preserve all world deltas, robot cell, facing, chassis, and `scrap_total`. Create one active legacy expedition with starter objective incomplete, `unbanked_scrap = scrap_total`, zero Cores/modules/modifier, and derived Alert 0. |
| Schema 2, relay true | Use stable objective ID `starter-relay-v1` at `(12,6)`, mark only that objective credited with a migration event ID, create later objectives deterministically when `WW-18` is installed, set derived Alert I, and preserve all other data. No reward is replayed. |
| Schema 2, chassis zero | Restore the current shutdown field and create `FAILED` with a pending compatibility settlement. Do not immediately forfeit, teleport, clear the run, or bank anything on first load. The player explicitly opens/accepts the failure summary. |
| Legacy scrap | Treat `scrap_total` as unbanked run scrap so it remains immediately spendable for repair and Refit. Do not silently move it to an inaccessible bank. |
| Missing new optional values | Apply conservative neutral defaults only within a recognized older migration step. Current-schema missing required fields are invalid; permissive current-schema repair is not allowed. |
| Unknown module/modifier ID | A current active-run module ID is invalid unless an explicit alias exists. A removed persisted modifier uses the documented neutral fallback while preserving the original ID in diagnostic metadata so the save can still load. |
| Primary corrupt, backup valid | Validate primary and `.bak` independently, select the valid candidate with the highest `write_sequence`, load it, retain the bad file under a diagnostic suffix, and rewrite only on the next committed save. |
| Interrupted `.tmp` | Never prefer an uncommitted temporary file over a valid primary/backup unless a repository transaction marker proves it was fully written and validated. Test this policy on native and exported Web storage. |
| Future schema | Preserve/quarantine it and return an explicit incompatible metadata state to title. Never clear it and never partially load world mutations. |
| Oversized/malicious JSON | Enforce file-size, array-length, string-length, coordinate, wallet, history, pickup, objective, and applied-event caps before allocating large runtime structures. Reject numeric coercions and duplicate cells/IDs. |
| Settlement interruption | Persist a preview and stable `settlement_id`; apply profile delta and terminal run marker in one repository snapshot. Repeated success/failure requests return the original committed result. Presentation and cleanup follow acknowledgement. |
| New-run interruption | Persist selected modifier and a recoverable launch marker in the same transaction that creates the next run, or retain a pending marker that deterministically finishes launch. An offer can never be consumed without a run being created. |

Canonical output sorts cell arrays and stable-ID arrays. Tests compare semantic equality and canonical re-save equality after migrate → save → reload → save. The repository applies validated candidate objects only after every section and cross-section invariant passes, preventing half-loaded terrain or economy.

## 13. Risks and rollback points

| Risk | Prevention and detection | Rollback point |
|---|---|---|
| Behavior drift during god-object extraction | Move one ownership cluster per package, retain compatibility getters temporarily, and run exact drive, Smash, relay, and hazard checks after every merge. | Revert to `a30db57` or the last package before `WW-02`; new typed files are isolated and removable. |
| Valid saves erased by partial schema work | Land repository and migrator plus fixtures before writer; validate detached candidates; preserve source and backup; fail future versions closed. | Last schema-2 release bundle and source commit; repository can remain read-only until migration passes. |
| Duplicate rewards, objectives, settlement, or modifier choice | Stable event and settlement IDs, consumed ledgers, edge-triggered outpost events, one transaction snapshot, and interruption tests. | Disable the new event consumer through coordinator configuration while preserving durable data for replay after a fix. |
| Unfair resume into Alert pressure | Never serialize transient nodes; re-arm only after safe delay or trigger transition outside sanctuary and contact radius. | Resume with a neutral suppressed director profile while retaining Alert and objective truth. |
| Aftershock removes shipped power | Baseline call graph and explicit invariant that the three-cell fan is universal. Tests cover fresh and migrated runs without module. | Disable only the enhancement capability; baseline `impact_charge.gd` footprint and effect calls remain. |
| Mobile gets trapped or receives extra verbs | One joystick and one Smash invariant, safe-area and exclusion rectangles, modal input cancellation, synthetic multitouch, and visible summary and retry controls. | Plain anchored controls and default handedness; no gameplay state depends on skins or outer-ring presentation. |
| Relay generation loads or scans the infinite world | Pure coordinate queries, capped candidate attempts, deterministic fallback, saved objective coordinates, and property tests on loaded-chunk count. | Retain the starter relay plus a prevalidated route-resource fallback for relays two and three under the same stable IDs. |
| Alert composition becomes accidental or overwhelming | Director owns run spawns, owner tags, exact budgets, safe annuli, corridors, gaps, sanctuary suppression, and no health inflation. | Revert profile Resource values or disable one profile consumer without changing save state. |
| Failure feels punitive or migrates old shutdown unfairly | Data-driven policy, explicit arithmetic, all-Cores and partial-scrap wording, world and profile preservation, and pending legacy settlement. | Change penalty Resource after telemetry; settlement version records policy used. Never retroactively recompute committed results. |
| Generated art obscures mechanics or breaks identity | Art bible, standalone-asset default, deterministic overlays above decoration, runtime-scale and accessibility review, and procedural fallbacks. | Remove catalogue entry or derivative; no simulation or save change is required. |
| Generated assets inflate Web payload or VRAM | Per-family budgets, derivative-only export, atlas reuse, compression and import tests, bundle-size and hash check, and mobile profiling. | Revert individual derivatives or use procedural fallback; retain masters outside export. |
| Web performance degrades under Alert III | Compact front geometry, visible-window iteration, pooled VFX, calibrated frame, input, and stream budgets, plus long soak. | Mobile-low decorative density and procedural cue fallback; gameplay timing and footprint remain unchanged. |
| Public host serves stale bundle | Clean output, exact bundle, stale deletion, immutable release ID or critical hashes, cache-busted clean browser, and visible build marker. | Redeploy the previous WebDev checkpoint and verify public rollback before changing source again. |
| Parallel branches merge incompatible assumptions | Freeze IDs and view models, assign exclusive hot-file owners, use reducer outputs, rebase on last green, and run fast verification after each merge. | Drop or rebase the nonintegrated branch; the integration branch remains playable after every accepted package. |
| Scope expands into caravan, narrative, or permanent talent systems | Package done conditions explicitly limit the expedition loop; hooks do not imply implementation. | Reject scope from this plan and place it in a future proposal after `WW-39`. |

Rollback favors reversible data and presentation. Balance changes live in versioned Resources. Generated visuals have procedural fallbacks. Encounter profiles can be disabled independently. Irreversible contracts, including the save envelope, stable IDs, settlement arithmetic, world-generation version, and lifecycle strings, require fixture-backed acceptance before first public write and cannot be casually renamed.

## 14. Balancing and performance targets

Targets are measured with local-only session telemetry and representative manual runs. A miss blocks balance sign-off; it does not trigger hidden automatic tuning or control changes.

| Target | Acceptance measurement | Tuning levers allowed | Forbidden shortcut |
|---|---|---|---|
| First relay | A fresh player or reference route reaches relay one within 45 seconds and understands automatic linking. | Signal visibility, onboarding copy, reversible route guidance, and starter surroundings. | Moving Cardinal faster, teleporting, or removing direct control. |
| First upgraded strike | A fresh player produces the first 40% or higher Smash within 60 seconds. | Charge gain and decay Resource, meter and cue clarity, and mobile run intent. | Granting free charge or adding an attack button. |
| Worm fight | Skilled four-hit fight under 25 seconds, at least one readable dodge, zero damage when cues are respected, and retreat remains valid. | Burrow, Intercept, Expose, and Dive durations; capped stagger extension; warning lead. | Lowering health solely to hit time, unavoidable spawn, or stunlock. |
| Refit choice | Median valid choice under 15 seconds; user identifies three effects, costs, affordability, installed state, and close action. | Card copy, layout, default focus, costs, and reversible art. | Auto-buy, hidden costs, hover-only detail, or an inventory grid. |
| Expedition | Representative neutral successful runs take 8–12 minutes, with three relays, roughly two to four worm engagements, one major storm crossing, and at least one push or retreat decision. | Relay spacing bands, profile delays, cooldowns and budgets, plus reward and cost Resources. | Increasing enemy health, changing movement speed, or counting summary and Refit delay as action pacing. |
| Failure | All Cores lost, default 50% run scrap lost via ceil rounding, clear immediate summary, and retry available without title-only escape. | Penalty Resource after telemetry and copy or presentation. | Deleting world mutations or profile bank, or auto-forfeiting legacy shutdown on load. |
| Streaming | Exactly 25 chunks, no more than 1,600 active cells, no more than 841 visible cells, bounded objective, drop, VFX, and entity counts, and no monotonic growth over ten runs. | Culling radius only through separate compatibility review; pooling, bounded histories, atlas reuse, and sample throttling. | Pinning remote chunks or deleting earned drops silently. |
| Web performance | After calibrated warm-up, desktop p95 no more than 16.7 ms and constrained mobile p95 no more than 33.3 ms on versioned reference profiles; bounded stream hitch, input latency, memory trend, payload, and startup requests. | Decorative density, particles, atlas size and compression, offscreen redraw, and pooling. | Reducing input sampling, hiding telegraphs, nondeterministic simulation, or claiming headless GPU timing. |
| Accessibility | Critical objective, danger, and result state survives muted audio, reduced motion, low flash, grayscale and common color-vision simulation, large text, and unsupported haptics. | Captions, shapes, patterns, icon and text redundancy, and layout reflow. | Color-only cues or disabling exact telegraphs. |

Initial costs, module scalar values, Alert cooldowns, modifier weights, particle counts, shake, audio levels, and visual intensity remain provisional until the owning research reducer and telemetry are accepted. The default balance Resource must reproduce `a30db57` values before any deliberate change.

## 15. Final definition of done

Walker's Wake is complete only when the following statements are simultaneously true on the same pushed and publicly verified release.

| Domain | Final requirement |
|---|---|
| Player loop | A player launches, drives directly, builds Impact Charge, uses the same one Smash input, activates three relays, experiences Alert I–III, optionally fights readable worms for Cores, uses one-run Refit, extracts and banks, chooses one of two modifiers, and begins a clean second expedition. |
| Baseline preservation | All eight desktop directions, proportional touch movement, run and coast, one contact frame, contact, two-cell, and three-cell Impact footprints, baseline high-charge fan, automatic relay, outpost, and pickup behavior, starter relay contest, hazard damage cadence, and infinite-stream bounds remain covered and green. |
| Worm counterplay | Burrow, Intercept, Expose, stagger, Dive, dispersal, defeat, exactly one Core plus scrap, fair retreat, persistence, and sub-25-second skilled play are implemented and readable on desktop and mobile. |
| Refit | Ram Plating, Aftershock enhancement, and Storm Seal are data-defined, transaction-safe, run-scoped, honestly described, input-equivalent, and observable in play; Refit takes under 15 seconds. |
| Run and settlement | Three stable streamed objectives, derived Alert, owner-directed encounters, sanctuary, automatic exact-cell extraction, fair idempotent failure, bank and profile separation, durable summaries, and relaunch reset all survive page reload at every boundary. |
| Modifiers | Hot Front, Brood Ground, and Dead Grid have stable IDs, persisted deterministic offers, installed consumers, neutral fallbacks, no reroll exploit, and exactly one-expedition lifetime. |
| Save safety | Schema-1 and schema-2 fixtures preserve all prior values and mutations; schema 3 round-trips canonically; backup, interruption, future, malformed, and oversized cases fail safely; no transient node state is serialized; settlement and launch are exactly once. |
| UX and accessibility | New players answer where to go, why move, and when to Smash. Decision HUD excludes default telemetry. Mobile has one joystick and one Smash button. Pointer, keyboard, and touch modals, large text, high readability, reduced motion, flash, and shake, captions, sound, haptic fallback, and handedness pass. |
| Art | Cardinal obeys identity and directional-sheet contracts; all world assets use coherent 2:1 perspective; only accepted GPT Image 2 runtime derivatives and any required concise source note enter Git; deterministic overlays remain authoritative; optional asset deletion boots through fallbacks. |
| Balance and performance | First relay is no more than 45 seconds, first upgraded strike no more than 60 seconds, worm is under 25 seconds, Refit is under 15 seconds, expedition is 8–12 minutes, ten-run soak has no leaks or duplication, and calibrated desktop and mobile Web budgets pass. |
| Delivery | The final clean export's immutable PCK pointer and byte size match WebDev, the cache-busted public URL passes desktop and mobile console, network, and WebGL checks, the focused commit is on the verified upstream, and the worktree is clean. |

No source or runtime package is complete because code exists, local smoke passes, or an image was generated. Completion means the smallest playable behavior, focused tests, fresh clean release, exact WebDev deployment, live smoke, focused Git checkpoint, and a usable rollback point exist together.
